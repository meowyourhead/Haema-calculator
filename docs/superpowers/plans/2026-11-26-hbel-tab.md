# HBEL Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an **HBEL** tab that suggests the correct LabWare HBEL comment from category chips (plus optional HbA2 / HbF % boxes), and a source-sheet view of the spreadsheet's content.

**Architecture:** All comments, sheet text and machine criteria live in one plain-text file `assets/hbel_comments.txt`, embedded with `include_str!` and parsed once (`src/hbel_data.rs`). Pure matching logic (`src/hbel_match.rs`) turns the user's inputs into a ranked suggestion. The panel (`src/hbel_panel.rs`) draws the results view and the source sheet view with the existing `ui.rs` helpers.

**Tech Stack:** Rust 2021, eframe/egui 0.31 (no new crates), `cargo test`, the existing `screenshot` feature under `xvfb-run`.

**Spec:** `docs/superpowers/specs/2026-11-26-hbel-tab-design.md` (read it; § references below point there). Source sheet: `/root/.claude/uploads/c1e7133a-54d4-5bf3-b476-9f50e4f4e44d/1d1c5694-HBEL_Comment.xlsx`.

## Global Constraints

- Codes are exactly 1 and 3–26 (sheet rows 29 and 31 = codes 25 and 26). Code 2 is never included.
- Comment text = spec §6, byte for byte. The criteria, remarks, examples and links come from the sheet verbatim (§5.6, §7). A newline inside a sheet cell becomes one space.
- Never include the yellow highlighting, the "Highlighted not added to LabWare comment yet" note, the stray "```" in F15, or "Column1".
- Reference ranges: HbA2 2.2–3.4 %, HbF 0–1.3 %.
- No new crates. The app makes no network requests; links open with `ctx.open_url`.
- Follow `RELEASING.md`: never commit `target/` or `.exe`.
- Work in all three palettes (Default, Genshin, Pokémon), in light and dark.
- Commit messages end with the session's `Co-Authored-By` / `Claude-Session` trailer lines.

## Review Focus

1. **HbA2 typed as "3,5" (comma decimal) or "3.5%".** The value must show as invalid and be ignored; it must never be read as 35. (The existing `field()` strips commas, so HBEL number boxes must not use its numeric filter.) Test in Task 3.
2. **A number outside 0–100 (e.g. "-1", "150").** Treated as invalid and ignored. Test in Task 3.
3. **The data file checked out with CRLF line endings** (Windows `core.autocrlf`). It must parse identically. Test in Task 1.
4. **The user types a number, then clicks a chip on the same row.** The number is cleared and the chip's range is used. Clicking the selected chip again clears the row. Test in Task 3.
5. **A search query with different case or surrounding spaces** ("  26xx0001 ") still finds code 26. Test in Task 5.

**Options per row** (key → label; the chip ranges are the spec §5.2 values):

| Row | key | label | options |
|---|---|---|---|
| Hba2 | `hba2` | HbA2 % | `low` Low `[0,2.2)` · `normal` Normal `[2.2,3.5)` · `borderline` Borderline `[3.5,4.0)` · `raised` Raised `[4.0,10]` · `over10` >10 `(10,100]` |
| Peak | `peak` | HbA2 peak | `normal` Normal · `split` Split · `degraded` Degradation / co-eluting |
| Hbf | `hbf` | HbF % | `normal` Normal `[0,1.3]` · `raised` Raised <5 `(1.3,5)` · `mid` 5–50 `[5,50]` · `over50` >50 `(50,100]` |
| Hb | `hb` | Hb | `normal` Normal · `low` Low · `markedly-low` Markedly low (<7) |
| Indices | `indices` | Indices | `normal` Normal · `micro-hypo` Micro/Hypo · `marked` Markedly decreased |
| Film | `film` | Film | `target` Target cells · `sphero` Spherocytes · `sickle` Sickle cells · `poikilo` Marked poikilocytosis |
| CWin | `c` | C window | `neg` (−) · `present` Present |
| SWin | `s` | S window | `neg` (−) · `present` Present |
| Hbh | `hbh` | HbH inclusions | `not-detected` Not detected · `detected` Detected |
| Hba1c | `hba1c` | HbA1c | `normal` Normal · `high` High |

**File syntax** (document it in a `#` comment block at the top of the data file):
- `#` starts a comment line. Blank lines are ignored. `\r` is stripped.
- `[N]` starts code N. `[resources]` starts the tab-wide links section, which accepts only `link:` lines.
- `key: value` lines, splitting on the first `:`.
  - `comment:` — exactly one per entry.
  - `groups:` — comma list of `normal`, `hbf`, `thal`, `variant`.
  - Repeatable: `remark:`, `example:` and `reference:`.
  - `link: Label | https://url` — also repeatable.
  - `set: Name` starts a named criteria set. Lines before any `set:` go into one unnamed set.
  - `sheet <Column>: text` adds a verbatim sheet line to the current set. Columns are A2, F, Hgb, RBC indices, C window, S window, Fe and HbH inclusion body.
  - `<row key>: <rule> [(assumed)] [(key)]` adds a criterion. Flags may be combined, as in `(assumed, key)`.
    - A numeric row's rule is a range: `A..B` (inclusive), `A..<B`, `>A` (up to 100 inclusive) or `<B` (from 0).
    - Any other row takes a comma list of option keys, meaning "any of".
- Errors: an unknown row or option key, a bad range, a duplicate code, a missing `comment:`, or a `sheet` / criterion line outside an entry.

### Task 3: Inputs and matching

**Files:**
- Create: `src/hbel_match.rs`
- Modify: `src/main.rs` (add `mod hbel_match;`)

**Interfaces:**
- Consumes: `Row`, `ROWS`, `Range`, `Rule`, `Entry` and `Library` from Task 1.
- Produces (all `pub` in `hbel_match`):
  - `struct Inputs { hba2: String, hbf: String, sel: [Option<usize>; 10], film: u8 }` (Clone, Default, PartialEq). `sel` is indexed by `Row::index()`.
  - `enum NumState { Empty, Valid(f64), Invalid }`
  - `enum Value { Num(f64), Span(Range), Opts(u8) }`
  - `Inputs` methods:
    - `number(&self, row: Row) -> NumState`. Uses `crate::logic::parse_number` on the raw string; a value is valid only when it is in 0..=100.
    - `value(&self, row: Row) -> Option<Value>`. A valid number gives `Num`, otherwise `sel` gives the option's `Span`. Categorical rows give `Opts(1 << i)`. Film gives `Opts(film)` when non-zero.
    - `chip_selected(&self, row: Row, i: usize) -> bool`. On numeric rows with a valid number, the chip whose range contains it is the one selected.
    - `click_chip(&mut self, row: Row, i: usize)`. Toggles the chip, clears that row's number string, and toggles the bit on Film.
    - `is_empty(&self) -> bool` and `clear(&mut self)`.
  - `enum Outcome { Match, Conflict, Neutral, KeyUnmet }`
  - `struct Eval { code: u8, set: usize, matches: usize, conflicts: Vec<Row>, unmet: Vec<Row>, blank: Vec<Row>, rows: Vec<(Row, Outcome)> }`. `blank` holds the rows with a non-assumed criterion that the user has not entered.
  - `Eval::fits(&self) -> bool` is `conflicts.is_empty() && unmet.is_empty() && matches >= 1`.
  - `fn evaluate(e: &Entry, inp: &Inputs) -> Eval`. Scores each set and returns the best by (fits, matches, fewest conflicts).
  - `enum State { Empty, Fits, NoFit }`
  - `struct Suggestion { state: State, top: Vec<Eval>, also: Vec<Eval> }`
  - `fn suggest(lib: &Library, inp: &Inputs) -> Suggestion`:
    - `top` is every fit with the highest match count, ordered by code.
    - `also` holds at most 3: first the other fits by (matches desc, code), then the near misses (`conflicts.len() + unmet.len() == 1 && matches >= 1`) in the same order.
  - `fn describe(c: &Criterion) -> String`, e.g. "Hb: Normal or Low" or "HbF: 5–50 %".
  - `fn hint(ev: &Eval, e: &Entry) -> Option<String>`:
    - A near miss gives `"needs " + describe(conflicting or unmet criterion)`.
    - A fit with non-empty `blank` gives `"also expects " + join(describe(...), ", ")`.
    - Otherwise `None`. Assumed criteria never appear in hints.

Per-row outcome rule:
- The row is not entered: `KeyUnmet` if the criterion is key, else `Neutral`.
- There is no criterion for the row: `Neutral`.
- Film: `Match` if the bitmasks intersect, else `Neutral`. Film never conflicts.
- `Num(x)` against `Range`: use `contains`.
- `Span` against `Range`: use `overlaps`.
- `Opts` against `AnyOf`: the bitmasks intersect.
- Anything else is a `Conflict`. A key criterion that is entered but conflicts counts as a conflict.
